# Materials Boundaries 低成本模型交接指南

**当前七项 PLA/PCL 阶段已按独立 CI 核对收尾；工程与材料扩展保持暂停。模板已完成限定范围验证，可在新的明确授权下交接小任务；次一级模型负责执行，独立评审保留。**

## 每次只发一个任务

1. 先填写 `task-input.example.json`：确定基线、允许改动的具体文件、选定配方、证据、检查命令、产物和停止点。`REPLACE_...`、缺失哈希或未确定授权都不能直接执行。
2. 低成本执行者只收到：任务清单、相关契约片段、所选证据和一个已有示例。不要附上全部聊天与历史账本。
3. 候选完成即冻结，交给另一位评审者。执行者的自检不是独立评审。身份、统计、来源权利或科学契约有疑问，升级处理，不让模型猜。
4. 评审通过后才单独派发 runtime integration。现有 integrator 只生成组合数据产物，不会自动修改运行时；模板也没有一键发布命令。
5. 最终验证必须绑定实际提交／文件哈希。通过、失败、跳过、未运行要分开；发现了多少测试不等于运行通过多少。
6. 仅在明确授权后发布到明确分支，核对远端 SHA 和该 SHA 的必要 CI。main 合并、release、部署、DOI 仍另行授权。到指定终点立即停，不自动选下一批。

## 三个最容易误判的地方

- `handoff_ready: true` 仅表示声明和机器契约满足，不表示科学批准、身份全球唯一、权利审查完成或已入库。候选的实际入库增量仍为 0。
- 例如 Ewurum 的 370 次执行只有 366 个不同测试；对 1887 个 root ID 仅覆盖 162 个，1725 个未运行。577 个 installed 测试、32 个 CLI 输出和 wheel smoke 另计，不能相加包装成全量通过。
- 七项 PLA/PCL 的运行时基线现已核对为 `3829ec97…`，包含 1175 + 24 = 1199 条实验项目记录。专项与 general CI 均已通过：Ubuntu 3.11／3.12 每版本 1869 通过、18 政策跳过、无未完成 ID；Windows 3.10／3.13 各为 512 通过、14 跳过的子集，不能写成 Windows 全量。详细范围见 `pause-state.json`，模板交接不自动授权下一批材料。

## 降本首先减少结构性重复

优先复用已有 formulation packet compiler 和 integration manifest v2；不要为每批材料默认复制专用 runner、workflow、历史投影与多层 inventory。仓库已有较重历史兼容负担，曾发生 Ubuntu 全量六小时超时。需要改大量历史绑定时，应暂停低成本执行并由维护者划定范围，而不是继续堆模板。

迭代先做经批准的聚焦检查，最终冻结版本再做必要验收；不能为了省钱删测试或把 scoped pass 写成 full pass。完整验收要求仍以仓库与当前审批为准，模板不能豁免。

## 失败时的回复格式

`动作｜对象｜预期与实际｜已完成工作｜暂停的依赖工作｜需要的具体决定`

权限拒绝不得换路线绕过。先确认不确定动作是否执行；仅在政策允许且有实质新证据时，拒绝后至多重试一次。身份／权利不明就 pending，哈希变化就重新冻结与评审，超时保留部分记录，不重复启动整套长任务。

公开入口见 `ONBOARDING.md`。任何人或 agent 都需自己的可用环境、合法证据和当前明确授权；不能继承他人凭据或默认继续开发。先运行只读 `dispatch_preflight.py`，只有 ready 且检查通过的清单才能在当前授权下派发；draft／archival 一律拒绝。

原生 Windows 模板验证为 **45 通过、0 失败、1 项不适用**，不是 46 次通过；旧失败保留。当前说明提交的远端状态与 CI 在发布后单独核对，不为回填自身 CI 再递归提交。
