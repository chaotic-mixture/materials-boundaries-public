# 分层验证（独立候选流程）

本入口不启动完整 SCC、不改变既有工作流，不将局部通过视为 SCC 接纳。
基线必须来自明确的冻结清单；工具重新核对其指纹，并自行计算全部新增、修改和删除文件，不能用手填文件列表隐藏影响范围。

## 使用

从本独立副本根目录运行（报告路径必须在源码目录外且尚不存在）：

```powershell
python -B scripts/run_layered_validation.py --baseline ../scc-layered-validation-evidence/baseline-r6.json --output ../scc-layered-validation-evidence/check-001.json
```

加 `--plan-only` 只查看范围，不运行测试。`--stage-timeout 120` 限制每个阶段；超时是失败，不是跳过或通过。每个阶段实时输出开始和完成事件。

## 顺序和范围

1. 版本前置：只执行已有的两个版本字面量、构建声明和 README 一致性测试，不运行该模块中的科学输出测试。
2. 历史前置：校验注册账本的指纹、SCC 注册链、当前 SCC 文件和文档的精确逆向恢复；直接执行 README、版权声明和版本测试文件的原始历史恢复路径。若存在性能候选代码桥，也检查其指纹。此层不重放整套材料图，也不证明所有历史行为正确。
3. 清单前置：检查核心分区清单指纹及结构，不发现或运行 1887 项测试。
4. 范围验证：本文档、说明文档的改动只需要上述有界检查；修改本入口时额外执行其分层规则测试。历史约束仍然有效：未登记的文档改动也可能在前置阶段失败，工具不会自动更新历史指纹。
5. 科学数据、计算代码、schema、工作流、未映射测试、删除文件等改动标记 `full_acceptance_required`，退出码 2，交由后续明确的验收任务处理；绝不自动启动全套。新增针对性映射须经过评审，不使用文件名猜测依赖来跳过回归。

阶段失败立即停止后续阶段。报告绑定本次完整输入清单和指纹，结束时重新比对；输入发生变化则报告失效。旧轮结果不会导入。`bounded_checks_passed` 只代表此轮前置及明确范围的检查通过。发布、合并和正式 SCC 接纳仍需各自完整证据，文档改动豁免不是发布授权。

本目录由 r6 冻结的 1289 个文件复制而来，与运行中的 r6 和性能优化候选隔离。这里只新增入口、流程说明和专项测试；没有修改已有历史账本或自动批准新基线。将来迁移到性能候选或后续 SCC 时，必须重新运行前置检查并单独审查未映射改动。
