# Language support

Materials Boundaries / 材料边界 provides human-readable CLI output and getting-started guides in four languages:

| Language | CLI code | Guide |
| --- | --- | --- |
| English | `en` | [Getting started](GETTING_STARTED.en.md) |
| 简体中文 | `zh` | [快速开始](GETTING_STARTED.zh.md) |
| 日本語 | `ja` | [はじめに](GETTING_STARTED.ja.md) |
| Deutsch | `de` | [Erste Schritte](GETTING_STARTED.de.md) |

The [terminology guide](TERMINOLOGY.md) distinguishes scientific categories and the meaning of applicability statuses. Scientific wording and translations are machine-assisted and have not received independent scientific or native-language review. This includes the English scientific explanations. Key parity is a software check, not a scientific or linguistic endorsement.

## Stable data, localized presentation

The UTF-8 dictionary is `materials_boundaries/data/locales.json`. Its contract is:

```json
{
  "schema_version": "1.0.0",
  "default_language": "en",
  "translation_review": "machine_assisted_not_scientifically_reviewed",
  "languages": {"en": {}, "zh": {}, "ja": {}, "de": {}}
}
```

Each language object maps the same flat, stable string keys to localized text. A translated label must never become a data key, rule identifier, source identifier, claim identifier, or enum value. Current strings have no interpolation placeholders. Version 0.2.0 added shear/E/ν labels, bound-kind and dependency labels, and explicit derived-envelope/Poisson-range warnings. Version 0.3.0 adds claim-type, dimension, SI-unit, evaluation-support, parameter and catalog-only fracture-model labels without changing the locale schema version.

- Numeric inputs and outputs, formulas, and the unit IDs `Pa`, `kPa`, `MPa`, `GPa`, `N/m`, and dimensionless `1` remain canonical. Fracture parameter unit IDs `J/m^2` and `m` are also canonical. Do not use localized decimal separators in JSON
- Status IDs remain `satisfied`, `violated`, and `unknown`. Translate their display labels only
- Source titles, authors, claim/observation names, original evidence text, input IDs, and other bibliographic or user-supplied text retain their stored wording; the catalog does not create translated source records
- `evaluate --json`, default `catalog` output, and explicit `catalog --json` output canonical JSON, independent of the selected display language. `catalog --text` opts into human-readable output
- `--lang en|zh|ja|de` selects the presentation language, either globally before the command or after the command; the last occurrence wins. English is the default
- `--help` localizes labels and descriptions. Command names, flags, choices, syntax, IDs, and machine-readable values remain canonical. Python errors and low-level schema diagnostics may remain English; localized output does not imply every developer-facing message is translated

## Catalog presentation and search

```sh
python -m materials_boundaries --lang zh catalog claims --text
python -m materials_boundaries catalog sources --id kochmann_milton_2014 --text --lang ja
python -m materials_boundaries --lang en catalog sources --query "Milton moduli" --text --lang de
python -m materials_boundaries --lang de catalog --help
```

The third command uses German because its final `--lang` takes precedence. JSON output uses the same `{schema_version, records}` structure and unchanged record values for every language, including empty results.

Catalog text translates labels and core explanations of reading, verification, and license status while retaining the canonical status codes and original bibliographic/evidence wording. A reading-status description states what was inspected, not that a theorem was independently proved. `software_tested_not_peer_reviewed` must not become scientific peer review in translation. A license status describes recorded reuse evidence; neither access, reading, nor testing grants reuse permission.

Search runs only on the specified stored fields, including the eighteen v0.4.0–v0.6.0, v0.8.0 and v0.9.0 claim records’ and two v0.7.0 observations’ authored display-name aliases in all four languages. Other localized labels and status explanations are not indexed. `--query` applies Unicode case folding and literal substring matching to whitespace-separated terms, requiring all terms to match; there is no stemming, ranking, fuzzy matching, automatic translation, or network search. Exact IDs and structured string filters remain case-sensitive in all languages. See [Catalog reference](CATALOG.md) for the fields, filters, errors, and Python API.

## Fallback and extension

Resolve a key in the selected language first, then in English. If neither contains it, display an explicit marker such as `[missing:key]`. Do not silently display an empty label or invent a translation. The `fallback_notice` key explains this behavior. Unsupported CLI language codes should be rejected rather than quietly treated as a supported translation.

Catalog status values remain visible as canonical codes. A newly introduced status without any display explanation is shown as its original code rather than given an invented explanation.

Since v0.20.1, each claims, sources or observations text render reads one fresh
locale snapshot when its first label is needed and reuses it only within that
invocation. A later render reads the file again, including after a same-size,
same-timestamp edit. Nested and concurrent renders have separate snapshots.
Standalone `translate` calls still read afresh for each call; prediction and
inspection rendering are unchanged. This is a presentation-only optimization,
with unchanged scientific validation, source reads, fallback and rendered text.
Locale loading retains its existing `json.loads` behavior, including last-wins
duplicate keys and acceptance of nonfinite values; this release does not add
strict locale validation. Authored dictionaries must still pass the QA below.

To add a key, add a nonempty translation to all four dictionaries. Preserve technical symbols, units, identifiers, and the distinction between missing applicability evidence and quantified uncertainty. To introduce interpolation later, require identical placeholder names in all translations and test escaped braces as well.

## Reproducible dictionary QA

From the repository root, the following uses only Python's standard library. It checks four-language key and placeholder parity, nonempty strings, metadata, and canonical technical tokens. It does not replace scientific or native-speaker review.

```sh
python - <<'PY'
import json
import string
from pathlib import Path

data = json.loads(Path('materials_boundaries/data/locales.json').read_text(encoding='utf-8'))
assert data['schema_version'] == '1.0.0'
assert data['default_language'] == 'en'
assert data['translation_review'] == 'machine_assisted_not_scientifically_reviewed'
languages = data['languages']
assert set(languages) == {'en', 'zh', 'ja', 'de'}
keys = set(languages['en'])
formatter = string.Formatter()
def placeholders(value):
    return {field for _, field, _, _ in formatter.parse(value) if field is not None}
for code, messages in languages.items():
    assert set(messages) == keys, code
    assert all(isinstance(v, str) and v.strip() for v in messages.values()), code
    for key in keys:
        assert placeholders(messages[key]) == placeholders(languages['en'][key]), (code, key)
    for token in ('K1 <= K2', 'G1 <= G2'):
        assert token in messages['well_ordered_definition'], (code, token)
    for key, token in [('hs_bulk', 'Hashin–Shtrikman'), ('reuss_bulk', 'Reuss'), ('voigt_bulk', 'Voigt'), ('hs_shear', 'Hashin–Shtrikman'), ('reuss_shear', 'Reuss'), ('voigt_shear', 'Voigt')]:
        assert token in messages[key], (code, key)
print(f'PASS: {len(languages)} languages, {len(keys)} identical nonempty keys per language')
PY
```

Integration checks should additionally compare `evaluate --json` and default/explicit catalog JSON for all four `--lang` values, exercise the fallback and missing-key paths, and check that representative Chinese, Japanese, and German labels appear in evaluation, catalog text, and help. Verify language selection before and after commands, last-occurrence precedence, unchanged canonical IDs and bibliographic/evidence text, and identical search results across display languages. These are presentation and software checks, not scientific validation or permission to reuse a source.

## Mechanical extension terminology

Translations must retain the distinction between a scalar K/G bound and a **derived conservative outer envelope** for E/ν. Never translate `derived_outer_envelope` into an optimal or tight joint bound. `joint_attainability: not_asserted` means that no common microstructure attaining the chosen K/G corner is established. “Same system” refers to the same instance, phase pairs, fractions, units and conditions, not a claim of specimen verification.

Poisson's ratio is dimensionless, may be negative or zero, and must remain strictly between −1 and 0.5. Translate the warning that rounding onto either boundary causes `numerical_range_error`; do not present a clipped boundary as valid. Preserve the HS-only dependency and no-fallback policy in all four languages.

Human-readable labels and help cover all eight evaluations. In v0.2.0, JSON schema version 1.1.0 applied to both evaluations and claims. In v0.3.0, evaluations retain 1.1.0 while the ten-record claims catalog uses 1.2.0; sources and the locale dictionary stay at 1.0.0. Localization must never change any version, dependency, numeric endpoint, unit, applicability state or computation state.

## Catalog-only fracture terminology and locale-independent search

Translate the meaning of a model estimate while retaining `claim_type: model_estimate`, `direction: prediction`, `bound_kind: null`, and `evaluation_support: catalog_only`. Do not turn a critical remote tensile stress estimate into a universal strength upper bound, an engineering allowable, a measured strength, or an executable evaluation. No per-instance applicability state or number is produced by these catalog records. Unknown or violated physical premises cannot justify applying the formula.

The existing six K/G records use `claim_type: theoretical_bound`; the two E/ν records use `claim_type: derived_outer_envelope`. These are canonical data codes, not translated labels. Legacy `bound_kind` codes remain unchanged. `quantity_dimension: pressure` pairs with `si_unit: Pa`, and `quantity_dimension: dimensionless` pairs with `si_unit: 1`; parameter dimensions and units are separately specified.

Across all four guides and text renderings, preserve the following distinctions:

- Plane stress uses E_prime = E; plane strain uses E_prime = E/(1−ν²)
- a is **half** the total central through-crack length 2a, not the full crack length
- Gc is critical energy release rate, not the shear modulus G; Gc = 2γ only in the ideal purely brittle case where surface creation is the only dissipation
- The homogeneous isotropic continuum, central-crack geometry, remote mode-I tension and small process-zone assumptions do not establish real specimen applicability
- The continuum formula must not be extrapolated to atomic crack sizes or a → 0
- Historical attribution and modern formula cross-checking have separate evidence roles; neither implies independent scientific review or reuse permission
