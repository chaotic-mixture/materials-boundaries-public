# 组合 r3 的隔离打包与安装核验

此证据只核验未接纳候选的打包、安装与数据库读取/导出，不改变原生数据，也不替代独立来源审阅。对应组合快照 `ea288ee80aae4b5bba931b5e62cb32cf6b3c8b805bf457084f52bde54a585b4f`。

外部构建目录包含从既有交付清单核对过的69个输入文件。仅在该外部副本中覆盖r3的三张数据库表，并将版本标为 `0.35.0+polymerpreview.20261103.r3`，防止与既有软件版本混淆。仓库版本、源码和原生表保持不变；未修改git索引。

生成的本地wheel SHA-256为 `30067d271aa63872ae53651e11bd9087fccf4d745f05c6921886043ceff8b863`。wheel仅包含预期软件负载与元数据，不包含候选目录、PDF/XML/XLSX原文或截图。不发布、上传或安装到用户日常环境。

实际核验包括：

- 全新Python 3.11虚拟环境中以 `--no-index --no-deps --no-cache-dir` 执行本地安装。
- 用 `-I -X utf8` 从环境内导入包，确认导入位置在临时环境的site-packages，不从仓库或PYTHONPATH读取。
- 已安装负载和wheel元数据逐文件比对；pip的direct_url指向同一本地wheel。该pip版本未在archive_info保存哈希，因此采用准确本地URL、wheel SHA-256、负载及元数据字节一致性验证，不虚构pip提供了哈希。
- 实际读取5180个身份、5190个状态、5223条性质，快照与冻结r3一致。
- 按来源跨全部分类核对：Şahin 10条、PBS 19条、PA12老化9条、NR 7条；不是聚合物分类内的计数。
- 环境内CLI导出Şahin来源并通过snapshot完整性核验。原有69个仓库输入逐文件保持不变。

## 失败与恢复记录

`FIRST_ATTEMPT_R3.json`：安装进程后收集日志时，`-I`忽略UTF-8环境变量，含中文路径的GBK输出导致解码异常和日志拼接错误。首次安装进程返回码未保留，不填写为成功；随后已观察到实际安装的精确版本。修正为显式 `-X utf8`。

`SECOND_ATTEMPT_R3.json`：报告误将NR的聚合物分类内1条当作来源总数。改为从冻结r3目录按全部分类计算预期数量；实际来源共7条。此错误发生在负载、元数据、快照和全局数量核对之后，不是数据图契约失败。

恢复使用同一wheel、构建输入与安装环境；未重建、未重装。`INSTALLED_VALIDATION_R3.json`记录最终通过的安装后验证，保留上述失败，不把它们合并成一次从未失败的测试。恢复不重跑已完成的历史回归或来源审计。

## 复现和范围

`build_and_verify.py`要求新的仓库外输出目录、旧交付的package-inputs清单、已绑定的r3原生表目录和本地setuptools/wheel工具目录。只在同一份中断输入需要恢复时使用`--resume-existing`；它必须核对完整构建输入和字节，不能用来套用其他快照。正常新运行会创建新环境，不覆盖已有构建。
